Поиск событий Apple в заданном диапазоне

2026-10-23 · Revision 1 · Implemented locally · Реализация согласована сообщением «погнали» и проверена. PR и деплой разрешены пользователем сообщением «Давай PR и деплой».

Проверенная причина

Повтор search_events_v2(query=JetBrains, start=2026-10-01T00:00:00+02:00, end=2026-11-01T00:00:00+01:00, max_results=30) вернул два события Google, complete=false и Apple provider_unavailable/retryable=true с текстом event search is not supported. Apple capabilities явно показывают operations.search=false. В internal/apple нет SearchEventsV2; application.searchEventsFanOut проверяет интерфейс SearchProviderV2 и завершает Apple-ветку до ListCalendars и CalDAV. Это отсутствие реализации, не свидетельство сетевого сбоя или потери доступа.

Прямой search_events_v2 с Apple calendar_id возвращает unsupported_capability без retryable=true. В fan-out обычная ошибка передаётся в failedSource, где код provider_unavailable и Retryable=true заданы безусловно. Отсюда ошибочная разница между двумя путями.

Живая проверка и рабочий путь

list_calendars успешно вернул три Apple-календаря. Для каждого вызван get_events_v2 с view=expanded за тот же октябрь: «Личный» — 1 событие, «Семья» — 0, «Напоминания» — 0; каждый ответ complete=true, без следующей страницы. Локальная проверка title, description и location без учёта регистра не нашла JetBrains. Это проверка событий VEVENT подключённых календарей в указанном окне, не поиск по задачам VTODO, скрытым аккаунтам или всей истории.

Рабочий read-only алгоритм уже сейчас: list_calendars → каждый Apple calendar_id → get_events_v2(view=expanded, start, end) → дочитать page_token, если есть → отфильтровать title/description/location. Ошибка любого источника или неполная страница должна оставлять результат неполным; пустой полный ответ означает отсутствие совпадений в выбранном диапазоне.

Предлагаемый минимальный контракт

  • Добавить Apple SearchEventsV2 поверх существующего ListEventsV2(view=expanded). Требовать обе границы start/end: без них вернуть unsupported_capability с пояснением о необходимости диапазона; не сканировать всю историю молча.
  • Искать подстроку query без учёта регистра в title, description и location. Это документированная локальная текстовая семантика, без обещания полного совпадения с Google Q или Microsoft search. Поля участников и вложений в поиск не входят.
  • Apple поддерживает default event type: фильтр только иных типов даёт пустой полный результат; default среди фильтров разрешает проверку событий. Соблюдать show_deleted и расширение повторов существующим адаптером.
  • Стабильно сортировать результат по времени и ID, соблюдать max_results и возвращать continuation token; токен привязывать к calendar/query/range/show_deleted/event_types и проверять до чтения. Пагинация не обещает snapshot при внешних изменениях источника. Не обрезать выдачу с complete=true без продолжения.
  • Поставить capabilities.operations.search=true с reason о bounded-only ограничении; обновить описание MCP/README, чтобы клиент передавал диапазон для общего поиска с Apple.
  • В unsupported-ветке fan-out создавать типизированный unsupported_capability; failedSource должен сохранять классификацию через providerFailure вместо безусловного provider_unavailable. complete=false сохраняется при любом провалившемся источнике. Реальные 429/5xx остаются retryable, unsupported не становится временной ошибкой.

Новые credential, OAuth scope, DB schema или write path не нужны. Нет изменений синхронизации и логики отменённых Google-серий из предыдущей работы.

Риски, восстановление, согласование

CalDAV fallback может читать больше объектов, чем возвращает окно; локальный текстовый поиск не устраняет стоимость существующего чтения. Нельзя выдавать неполный результат за доказательство отсутствия событий. Existing Apple malformed-object completeness поведение требует сохранения и явной оценки при реализации, без скрытого расширения этого PR. Offset pagination чувствительна к параллельным внешним правкам; snapshot-кэш не входит в минимальный контракт.

Локальный откат — только собственного patch. Production-откат отдельно согласовывается. Текущий checkout содержит чужую незавершённую работу Apple discovery/list-calendars и документацию; она не менялась. Запрошена только диагностика и предложение: Revision 1 утверждена сообщением пользователя «погнали». Локальная реализация завершена; Commit, push, PR, merge и деплой после CI отдельно разрешены сообщением «Давай PR и деплой». Открытых блокирующих технических вопросов нет; bounded-only и подстрочная семантика являются предлагаемым выбором для согласования.

Фактическая реализация и принятие

Изменены internal/apple/events_v2.go, новые search_v2.go и search_v2_test.go; internal/application/actions.go, fanout.go и новый search_test.go; internal/mcpserver/tools_v2.go и новый search_test.go; README.md. Apple реализует SearchProviderV2, объявляет search=true с ограничением диапазона, ищет после локального раскрытия повторов и фильтрует отмены согласно show_deleted. Отдельно проверяется полуоткрытое окно [start,end). Размер страницы по умолчанию 250, максимум 2500; continuation token содержит version, SHA-256 контекста запроса и offset. Отрицательный limit и повреждённый/чужой токен отклоняются до CalDAV.

Поиск использует строгий вариант существующего чтения: пропуск повреждённого объекта даёт ошибку, а обычный ListEventsV2 сохраняет прежнее поведение. В fan-out тип ошибки сохраняется через providerFailure; копия error получает контекст источника без изменения исходного указателя. Аналогичная unsupported-ветка списка V2 тоже типизирована, поскольку использует общий обработчик. MCP end-to-end тест вызывает настоящий Apple adapter с fake CalDAV и fake Google, дочитывает несколько Apple-страниц и проверяет неполный unbounded поиск. Проверены Unicode, поля поиска, пустой результат, default event type, DST, all-day, повторы/исключения, отмены, границы окна, неправильный token, context cancellation, provider errors 403/429/503 и повреждённые объекты.

Red до реализации: нет SearchProviderV2 и неверная классификация unsupported/403/429. Green после исправления: focused race suite и полный Go race suite прошли, vet прошёл. Перед завершением просмотрен собственный diff. Подагентов не было; пользовательские dirty/untracked файлы сохранены. После fetch origin/main целевые исходники и README совпали с main; для локальной реализации сохранён текущий checkout codex/google-orphan-occurrence вместо переноса чужих незакоммиченных изменений. Новая ветка и внешние действия не выполнялись; для будущей публикации нужен отдельный перенос собственного patch на актуальный main. Это сознательное отклонение только от Git-последовательности, не от согласованного поведения.
