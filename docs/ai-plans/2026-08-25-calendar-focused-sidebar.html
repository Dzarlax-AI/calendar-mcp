Calendar-focused sidebar

Status: implemented and independently reviewed on 2026-08-25.

Goal

Make /app a focused daily calendar surface, following the supplied Fantastical reference: the sidebar supports navigating dates and choosing visible calendars, while configuration does not compete with the calendar.

Current behaviour

CalendarSidebar mixes five global destinations (Calendar, Connections, Sync Rules, Runs, Settings) with New event, the mini-calendar, and calendar visibility filters. The same operational destinations already have separate routes and dedicated pages.

Desired behaviour

  • The calendar sidebar contains only: New event, mini-calendar/date navigation, and visible-calendar toggles.
  • Connections, Sync Rules, Runs, Settings, and diagnostics are removed from the /app sidebar, but remain reachable through their existing URLs and one compact toolbar Manage menu.
  • On compact screens, the “Calendars” sheet exposes only calendar controls; it does not become a hidden settings drawer.
  • No changes to OAuth, sync, MCP, calendar selection persistence, or event CRUD behaviour.

Likely files

  • frontend/src/features/calendar/CalendarPage.tsx — simplify CalendarSidebar, add an accessible Manage overflow menu in the toolbar, and remove now-unused navigation imports.
  • frontend/src/styles/app.css — remove obsolete calendar-sidebar navigation styling, add menu positioning/focus styles, and rebalance sidebar spacing.
  • Frontend tests — preserve calendar filtering and add a narrow regression check if the extracted sidebar structure has a testable seam.

Implementation and QA

  1. Remove global navigation from the calendar sidebar without deleting routes or control-plane screens.
  2. Add one subtle toolbar Manage trigger that opens links to the existing Connections, Sync Rules, Runs, and Settings pages. Do not embed those pages in a modal or duplicate their state.
  3. Keep the primary calendar actions and ensure keyboard labels remain accurate.
  4. Check desktop and compact layouts for usable calendar toggles, no empty divider, and no layout shift.
  5. Run frontend tests, typecheck, build, git diff --check, then visually verify the calendar and mobile calendar-filter sheet.

Agent allocation

  1. Implementer (Terra): make the coupled sidebar, toolbar-menu, CSS, and focused frontend-test changes. This is one lane because the menu state, keyboard behaviour, and responsive styles share the same component and must not be edited concurrently.
  2. Specification reviewer (Luna): read the resulting diff without editing; verify the approved scope, preserved routes, menu content, diagnostics visibility, and every acceptance criterion.
  3. Quality reviewer (Luna): after spec approval, inspect accessibility semantics, focus/Escape/click-outside handling, responsive CSS, and test coverage. Any finding returns to the implementer, then is re-reviewed.
  4. Root integration: inspect the final diff, run the integrated frontend checks and desktop/mobile visual smoke path, and report only verified results.

Acceptance criteria

  • On desktop /app, the sidebar contains New event, mini-calendar/date navigation, and calendar visibility toggles only.
  • On /app, the sidebar has no Calendar, Connections, Sync Rules, Runs, or Settings links.
  • The compact/mobile Calendars sheet has the same calendar-only content; Escape, scrim-close, focus handling, and accessible labels still work.
  • The toolbar Manage trigger has an accessible name, reports expanded state, closes on Escape/click outside/selection, restores focus to its trigger, and remains usable at 320px wide.
  • Calendar selection persists, Show all calendars still works, mini-calendar date selection still changes the main view, and New event still opens the existing modal.
  • /connections, /rules, /rules/new, /runs, /settings, and /diagnostics retain their routes and their current global navigation.

Risks and rollback

The main risk is discoverability of occasional administration pages. The Manage menu addresses it while keeping configuration out of the primary viewing surface. The existing routes and global sidebar stay intact; rollback is a small restoration of the calendar-sidebar navigation and removal of the menu.

Approval gate
Approve this plan to implement the calendar-only sidebar plus its compact toolbar Manage menu. It deliberately does not rebuild administration pages inside a modal.
