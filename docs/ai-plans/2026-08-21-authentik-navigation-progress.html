Authentik-safe navigation and action progress

Implemented locally — commit, push, and deployment pending

Task summary

Stop HTMX from turning Authentik authentication redirects into cross-origin XHR failures, and give users immediate local feedback after they start a connection or submit another potentially slow action.

Current behavior and confirmed cause

  • internal/web/templates/app.html applies hx-boost="true" to the entire authenticated application.
  • HTMX therefore converts ordinary links and POST forms into XHR requests.
  • When the Authentik session is absent or expired, forward auth redirects that XHR from calendar.dzarlax.dev to auth.dzarlax.dev. The browser blocks the cross-origin XHR and reports a CORS failure.
  • The earlier hx-boost="false" OAuth-link exception protects only two links. Navigation and Apple/rule forms remain affected.
  • No explicit partial-page HTMX operations exist in the application template, so global boosting currently provides no required application behavior.

Approved UX design

  • Use normal browser navigation and form submission throughout the authenticated UI. An Authentik challenge then becomes a top-level redirect instead of a CORS-blocked XHR.
  • Only the activated action control enters a busy state. It shows a compact CSS spinner and contextual text such as Connecting…, Verifying…, Deleting…, Saving…, or Starting….
  • Disable submitted buttons immediately to prevent duplicate writes. Links use aria-disabled and ignore repeat clicks while navigation begins.
  • Do not show a global overlay or claim success. The busy state means only that the browser started the request; success and errors remain server-rendered after navigation.
  • Use a small first-party JavaScript asset and existing first-party CSS. No runtime CDN or new dependency is introduced.

Likely file changes

  • internal/web/templates/app.html — remove the global HTMX boost, load the local progress script, and add contextual pending labels to actionable links and submit buttons.
  • internal/web/assets/app.js — add narrowly scoped click and submit handlers for local busy states.
  • internal/web/assets/app.css — style the spinner and disabled/busy controls, including reduced-motion behavior.
  • internal/web/server_test.go — add regression coverage for normal navigation, embedded first-party assets, and required pending-state hooks.
  • This plan — record the implementation, verification evidence, final deployed image digest, limitations, and follow-ups after completion.

  4. Add pending labels to OAuth connection links and all mutating form buttons. Hash-only and ordinary read-navigation links remain unchanged.
  5. Add the dependency-free progress script. Handle valid form submission through the submit event and link navigation through click; preserve button dimensions, original accessibility text, and normal browser semantics.
  6. Add spinner, busy, disabled, and prefers-reduced-motion styles.
  7. Run targeted tests, the full race suite, vet, and build.
  8. After a separate deployment authorization, push the commit, wait for CI, deploy only calendar-serve by immutable image digest, and verify the real authentication and connection path. Do not change the legacy MCP service or other shared services.

Manual QA checklist

  • With a valid Authentik session, click Google/Microsoft Add account and Reconnect: the clicked control immediately shows Connecting…, then OAuth opens as a top-level page.
  • With an expired Authentik session, open an app link and submit a safe test action: the browser reaches Authentik without a CORS error.
  • On a dedicated test calendar/account, submit Apple verification and rule actions: only the submitted button becomes busy and duplicate submission is blocked.
  • Trigger a validation or server error: after navigation, the control is restored by the new page and the existing flash/error state remains visible.
  • Confirm keyboard activation, focus visibility, narrow-screen layout, and reduced-motion behavior.

Risks and edge cases

  • A POST interrupted by an expired Authentik session may not preserve entered form values through reauthentication. This change fixes the CORS dead end but does not promise POST replay; replaying mutations automatically would be unsafe.
  • Disabling a submit button too early can omit its name/value from form data. Current submit buttons carry no form values, and the handler will run only after browser validation succeeds.
  • A navigation that is cancelled by the browser can leave a link visually busy on the current page. Restore it on pageshow, including back/forward cache restoration.
  • Real calendar QA must use an empty or dedicated test calendar with invites and notifications disabled.

Assumptions and non-goals

  • The server-rendered application does not require partial-page HTMX swaps.
  • This change does not alter OAuth scopes, provider credentials, Authentik configuration, API contracts, database schema, or sync behavior.
  • This change does not add progress percentages, background-job polling, optimistic success states, or automatic mutation retries.
