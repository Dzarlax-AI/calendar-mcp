Calendar Native Responsive UX

Implemented locally; PR prepared

Task summary

Make the unified calendar native-feeling and predictable on mobile, tablet, and desktop. Preserve full calendar names, add correct sheet/overlay behavior, keep New event discoverable, and protect the FullCalendar canvas from responsive collapse.

Baseline: 8b850b9, branch fix/calendar-sync-protocol-isolation. No production data or credentials are in scope.

Confirmed current behavior

  • Mobile filters cover the calendar without a scrim, leaving the underlying UI visible and apparently actionable.
  • Current-source browser evidence measured .calendar-filter as 15px 10px 189px 0px; the name is trapped in a 10px grid track because the checkbox is absolutely positioned.
  • The date chevron visually promises a picker but currently navigates to Today.
  • Desktop/tablet fixed panes compete with the center canvas; the primary event action disappears with the sidebar.

Web-first, native-ready constraints

  • Keep calendar/event domain types, capabilities, recurrence scopes, sync statuses, error codes, and mutation outcomes outside FullCalendar-specific callbacks.
  • Make surface state serializable and portable: none | filters | event | create | scope.
  • Define persistence/deep-link behavior for date, view, selected calendars, and selected event; localStorage must not be the only source of truth.
  • Make timezone, DST, all-day exclusive-end, multi-day, and recurring-scope behavior explicit and shared by future clients.
  • Use semantic design tokens and preserve cached/stale/degraded/failed read-model semantics.
  • Keep invite/notification suppression and mutation warnings in the server outcome contract.

Native app, PWA install, push notifications, background refresh, and platform-specific UI are intentionally deferred; this pass keeps them feasible.

Implementation waves

  1. Terra freezes the surface state, identity, ARIA, and date-view contract.
  2. Terra implements React/state behavior; Luna independently implements CSS/layout using the frozen class contract.
  3. Root integrates, seeds disposable SQLite fixtures, and captures browser evidence at 390, 430, 768, 1024, 1280, and 1440px.
  4. Sol reviews the integrated diff and evidence. At most one focused correction turn is allowed.
  5. PR, merge, deploy, and external notifications remain separate approvals.

Concrete implementation scope

  • Introduce one surface state: none | filters | event | create | scope.
  • Add scrim, outside/Escape close, focus return, inert background, and modal semantics.
  • Fix calendar grid to 15px minmax(0,1fr) auto; retain full name and provider/account identity.
  • Keep New event visible in the toolbar at every width.
  • Use honest date affordance: real date picker or no chevron.
  • Move sync status below the toolbar; separate success/info/warning/error visual semantics.
  • Use 44px hit areas, 100dvh, safe-area insets, synchronized mini-calendar, and aria-pressed view controls.

Implementation outcome

  • Terra updated frontend/src/features/calendar/CalendarPage.tsx with serializable surface state, accessible sheets, persistent toolbar action, honest date label, view persistence, status/notice intent, and calendar accessibility labels.
  • Luna updated frontend/src/styles/app.css with the corrected name grid, responsive desktop/tablet/mobile layout, scrim and sheet transitions, 44px targets, 100dvh, safe-area handling, status strip, and reduced-motion support.
  • Checks passed: frontend 21/21 tests and production build; Go tests and vet; diff check.
  • Browser evidence passed at 500x844, 1024x768, and 1440x900: no horizontal overflow; mobile filters open as a dialog with scrim, inert main content, focus management, and Escape close; toolbar retains New event.
  • Limitation: the disposable local browser fixture had zero connected providers, so long calendar names were validated through the corrected computed grid/static contract rather than populated provider rows.

Risks and rollback

  • Overlay state can interfere with recurrence/create dialogs; cover transitions with tests.
  • FullCalendar may need updateSize() after layout changes.
  • Safari dynamic chrome can clip sheets; test dvh and safe-area behavior.
  • Rollback is a bounded UI revert to the pre-change layout; no database or provider migration is planned.
