Calendar Density and Sidebar Polish

Implemented locally — ready for review

Task summary

Address the visual-audit findings in Calendar: overlapping timed events, event-card density, all-day overflow, mini-calendar alignment, calendar-list label space, and toolbar grouping. This is presentation-only work: no provider, event, authentication, or storage contract changes.

Current behavior

  • FullCalendar is configured in CalendarPage.tsx with dayMaxEvents={3}, but no explicit timed-event overlap policy or all-day stack policy.
  • Custom event markup renders time/title and an optional location; detailed events use CSS line clamping. The visual audit shows an overlapping event covering the adjacent card and tight lower padding.
  • The sidebar mini calendar uses a seven-column CSS grid and centered day controls. Calendar names and provider labels share a single row, so long names truncate prematurely.
  • The existing visual-regression harness has deterministic mock events including overlaps, all-day events, long titles, locations, and responsive screenshots. It can become the acceptance fixture for these fixes.

Desired behavior

  • Timed events that overlap display side by side without obscuring each other; each remains clickable and readable.
  • Event cards preserve clear hierarchy: readable secondary location, consistent interior spacing, and no text touching the bottom edge.
  • The all-day row caps visible items intentionally and uses FullCalendar’s +X more expansion rather than an unbounded or silently clipped row.
  • The mini-calendar is visually centered; long calendar names get priority space, with provider metadata shifted to a quieter second line where needed.
  • The date/navigation group and view controls remain visually grouped with no artificial empty space or overlap at desktop, tablet, and phone widths.

Proposed implementation

  1. Set FullCalendar’s timed-overlap behavior to side-by-side placement and verify its drag/click hit areas with synthetic concurrent events.
  2. Refine event-card padding, line height, and location typography; retain clamping so long metadata does not grow a short event beyond its time slot.
  3. Set and test a bounded all-day stack. Verify the existing +X more affordance opens the correct event list in week and month contexts.
  4. Normalize the mini-calendar grid geometry and revise calendar-list layout into name-first plus compact provider metadata, without weakening checkbox labels or read-only indication.
  5. Adjust toolbar group alignment only where visual screenshots prove a remaining gap; preserve the new compact calendar/refresh controls and phone view selector.
  6. Add focused unit assertions where helper behavior is introduced and visual/interaction assertions for overlap, all-day overflow, long labels, and key viewport breakpoints.

Validation and manual QA

  • npm --prefix frontend run typecheck, npm --prefix frontend test, npm --prefix frontend run test:e2e:mocks, and npm --prefix frontend run build.
  • Browser checks at 390×844, 582×1000, 768×1024, 1120×1234, and 1440×900: no card text overlap, no toolbar collision, no unexpected page-width scroll.
  • Open a day with four all-day fixture events; confirm visible cap, +X more, keyboard access, and event selection.
  • Check an overlap at 9:00–10:30: both cards have distinct bounding boxes and can be clicked independently.

Risks and assumptions

  • FullCalendar’s all-day expansion behavior differs by view. The desired cap will be confirmed against the installed version before asserting a specific popover implementation.
  • Disabling timed-event overlap consumes more horizontal width; narrow Week remains horizontally scrollable by design, while Day remains the practical phone default.
  • Provider metadata must remain available to assistive technology and for same-name calendars, even if visually secondary.
