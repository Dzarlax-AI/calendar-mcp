Calendar Sync Raw Artifacts

Approval required before implementation

Task summary

Add a bounded, encrypted raw-artifact store for object-level calendar sync failures so malformed Apple .ics and Google event responses can be inspected and repaired without losing the existing cached read model.

Current behavior

  • cached_events.payload_json contains only normalized EventV2; it is not raw provider data.
  • calendar_sync_quarantine stores object ID, ETag, error code, timestamps, and retry counters, but no payload or provider reason.
  • Apple reads the response body in internal/apple/event_sync.go, then discards it when media type or iCalendar parsing fails. The current production Apple calendar reproduces 11 such objects.
  • Google warnings similarly preserve only a bounded object identity and protocol code.

Desired behavior and boundaries

  • On an object-scoped protocol failure, retain a diagnostic artifact linked to the quarantine row.
  • Store raw bytes encrypted with the existing CALENDAR_ENCRYPTION_KEY; never put raw provider payload into ordinary event JSON or logs.
  • Cap raw payload size at 256 KiB. Persist a SHA-256, content type, HTTP status, bounded provider reason, truncation flag, and capture/expiry timestamps.
  • Keep normal event reads and cached-event behavior unchanged. Existing quarantined rows are populated on their next repair attempt; no production data rewrite is required.
  • Provide an internal, authenticated diagnostic read path or operator query that decrypts one artifact only after explicit authorization; do not expose it in the normal calendar UI.

Likely files

  • internal/calendar/event_sync.go — extend the internal warning/diagnostic contract without exposing raw payload in errors.
  • internal/apple/event_sync.go, internal/google/event_sync.go — attach bounded raw bytes and provider metadata at the failure boundary.
  • internal/credentials/crypto.go or a small adjacent helper — use AES-GCM with artifact-specific associated data.
  • internal/storage/models.go, internal/storage/event_cache.go — persist, read, expire, and transactionally link artifacts to quarantine.
  • internal/storage/migrations/postgres/004_event_sync_raw_artifacts.sql and SQLite equivalent — add the artifact table and indexes.
  • internal/web/api.go and focused API tests — authenticated operator-only diagnostic read path, if the existing API surface supports it without widening permissions.
  • internal/apple/event_sync_test.go, internal/google/event_sync_test.go, internal/storage/event_cache_test.go — provider fixtures, encryption, truncation, expiry, and quarantine linkage.

Implementation steps

  1. Freeze a provider-neutral diagnostic type: object ID/ETag, status, content type, bounded reason, raw bytes, hash, and truncation state. Keep cursors, credentials, URLs, and response bodies out of errors/logs.
  2. Add the encrypted artifact table keyed by (calendar_id, object_id, etag), with expires_at and a lookup index for active quarantine.
  3. Capture raw bytes before parsing in Apple and at the equivalent Google object failure boundary; apply the size cap and hash before storage.
  4. Make the quarantine transaction upsert the artifact and quarantine row atomically. On a changed ETag, replace the artifact and reset retry metadata.
  5. Add bounded cleanup of expired artifacts and a narrowly authenticated diagnostic read operation. Do not add raw payloads to ordinary list-events responses.
  6. Run focused tests, then the repository race suite and vet. Update this plan with actual changes and limitations after implementation.

Tests and QA

  • Provider fixture proves malformed/non-text/calendar responses retain bounded diagnostics while valid events still sync.
  • Storage test proves ciphertext is not plaintext, decrypts with the correct associated data, rejects tampering, replaces on ETag change, and expires after retention.
  • Quarantine test proves artifact and quarantine state commit together and retry behavior remains unchanged.
  • API test proves only the authenticated operator path can read one artifact and normal event endpoints never include raw data.
  • go test -race -count=1 ./..., go vet ./..., and git diff --check.
  • Manual QA uses the local read-only Apple harness and verifies the 11 current objects become inspectable without mutating provider events.

Risks and rollback

  • Raw calendar data is sensitive. Encryption, size limits, retention, and strict authorization are mandatory; plaintext logging is forbidden.
  • Provider payloads can be HTML/proxy errors rather than iCalendar/JSON. Store bounded bytes plus metadata, never assume the media type.
  • Artifact storage must not block or fail an otherwise valid sync page. If artifact persistence fails, preserve the existing safe quarantine path and surface a storage error.
  • Rollback is a code/image rollback; the additive table may remain unused. A follow-up migration can delete expired artifacts, but no cached events or provider objects should be deleted.

Open questions

  • Should the diagnostic read path be a backend-only admin endpoint, or is SQL/operator tooling sufficient for this PR?
  • Is a 7-day or 30-day raw retention period acceptable?
  • Should the 256 KiB cap be configurable, or fixed to keep the security review small?

Approval gate

Implementation was approved and completed in the working tree. The change is additive, read-only with respect to providers, and does not include deployment or production data cleanup.

Implementation result

  • Added schema version 4 with encrypted raw-artifact tables for PostgreSQL and SQLite.
  • Apple and Google protocol warnings now carry bounded diagnostics into storage; AES-GCM encryption, SHA-256, 256 KiB cap, and seven-day expiry are enforced.
  • Worker cleanup removes expired artifacts. A CSRF-protected POST /api/ui/sync-artifact diagnostic read path accepts identifiers in the JSON body, requires an explicit UI_RAW_ARTIFACT_USERS allowlist, and returns base64 payload plus metadata; ordinary event APIs are unchanged.
  • Added provider and storage regression coverage. No provider CRUD, production database cleanup, commit, push, merge, or deploy was performed.
  • Checks passed: go test -race -count=1 ./..., go vet ./..., git diff --check.

Known limitation: currently captured provider reason is populated only when an adapter has a bounded reason available; Apple malformed iCalendar failures expose status/content-type/raw bytes but not a fabricated human title.
