Результаты переноса

Миграции 001–028 совпадают с main. Обновление с 028 проверено на SQLite и PostgreSQL. Новым календарям Google, появившимся при обычном листинге, нужны проверенные права на детали. Листинг сохраняет проекции прежних календарей, а reconnect открывает кешированное чтение новых.

Пройдено 1 483 Go-проверки с -race и PostgreSQL, go vet, серверная сборка, сборка frontend и 94 теста Vitest. Chromium прошёл девять сценариев отзыва и три сценария восстановления Apple. Astra 6.2 перепроверила замечания по доступности после reconnect, первичному bootstrap, смене выбора и повторному чтению заблокированного календаря.

Три пары с резервным SQL-путём той же ветки дали 9,150 → 6,566 с для обычного обхода 16 источников с фоном и 8,147 → 6,022 с для набора с мастерами. Медианы парных изменений составили −28,4% и −27,0%. Состав, порядок и ограничения размера выдачи совпали. В раннем замере старой ветки было 4,903 с с другим темпом фоновых записей.

Тяжёлое серверное чтение UI в 12 парах с прежней веткой дало 199,5 → 114,5 мс. В каждой версии использовалась своя синтетическая БД с тем же набором событий. Буфер 8 МиБ / 8 192 строки и один слот SQLite сохранены.
