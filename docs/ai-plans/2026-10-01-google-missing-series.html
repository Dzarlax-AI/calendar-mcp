Синхронизация Google: недоступная родительская серия

2026-10-01 · Ревизия 2 · Implemented · Локальная реализация и проверки завершены.

Проверенная причина

Три dry-run запуска Google → Google завершились ошибкой. GET экземпляра события возвращает 200, GET его родительской серии — 404. Чтение series и expanded работает; режим both падает при загрузке родителя в internal/google/events_v2.go. В sync_runs сохраняется общий sync_failed. Проверка текущего окна после окончания события проходит, но дефект остаётся.

Согласованное поведение — ревизия 2

Пользователь согласовал копирование доступного экземпляра как самостоятельного события сообщением «Давай да» после обсуждения отсутствующего родителя.

  • Только 404 при загрузке родителя разрешает fallback. Поля экземпляра и ссылка на источник сохраняются.
  • Экземпляр копируется отдельно со стабильным mapping и sync marker; повторный запуск обновляет ту же копию.
  • Mapping хранит исходную серию и режим копирования по экземплярам. При восстановлении родителя эта серия продолжает копироваться по экземплярам в пределах окна правила, без создания повторяющейся копии и дубликатов. Это намеренный режим, а не автоматическая миграция в recurrence.
  • Если серия уже скопирована до потери доступа, работа продолжается через существующую целевую серию; отдельная дублирующая копия не создаётся.
  • Отменённые экземпляры удаляют только связанную копию. 403, 429, 5xx и ошибки авторизации не подавляются.
  • История показывает предупреждение о копировании серии по экземплярам. Уведомления отключены; реальные записи на сервере не запускаются.

Фактические изменения

  • Google ListEventsV2: строго 404 при загрузке родителя маркирует экземпляр orphanOccurrence; поля источника сохранены. Отрицательный результат кэшируется в пределах страницы. Другие ошибки возвращаются вызывающему коду.
  • Sync engine: отдельные копии с отключёнными уведомлениями, исходным идентификатором, original_start, sync marker и mapping detached_occurrence. SourceSeriesID сохраняет режим по экземплярам. Изменения и отмена применяются к связанной целевой копии.
  • Восстановленный родитель не создаёт дублирующую серию. Уже существующая целевая серия используется для обновления её экземпляра. Режим отдельной копии сохраняется как pending_create intent до provider write; sync marker восстанавливает копию после сбоя до финализации mapping. Это исключает массовые target lookup обычных экземпляров. При отмене pending intent проверяется только маркер этого экземпляра. UID отдельной копии стабилен и уникален для правила/экземпляра; Apple updates/deletes используют top-level scope. Перед сохранением нового hash восстановленная копия обновляется при необходимости.
  • Worker сохраняет bounded-предупреждение в существующем поле summary без миграции схемы; browser API пропускает только точную безопасную строку. Экран Recent activity теперь показывает пояснение результата запуска.

Риски и восстановление

Недоступный родитель не считается удалением экземпляра. Скопированная серия остаётся в режиме по экземплярам в пределах окна правила; автоматического перевода обратно в RRULE нет. Подавляются только 404 родителя, не другие ошибки провайдера. Откат локального изменения — точечное восстановление только внесённых строк; посторонние untracked-файлы сохраняются. Production-откат и изменение данных вне этой работы.

Согласование и результаты

Ревизия 1 с пропуском события заменена согласованным копированием отдельного экземпляра в ревизии 2. Разрешены локальные изменения и тесты. Запрос «давай деплой через pr» разрешил commit, push, PR, merge и деплой после успешного CI. Реальная запись событий в календари не входит в проверку релиза. Результаты приведены выше. Релиз: новая ветка codex/google-orphan-occurrence от origin/main. Go race suite и все 41 frontend-тест прошли на этой базе. После merge: CI-образ, pin digest для API и worker через минимальный Compose override без изменения .env, health/auth проверки и пробный запуск без записи событий. Конфигурация до релиза и прежний digest сохраняются для восстановления; production-откат требует отдельного решения, если сервис не стартует.
